# T032 — HTTPS on the LAN (no SSH tunnel)

**Branch:** `task/T032-https-lan` · **Mode:** Code · **Owner:** Kilo Code · **Reviewer:** Claude Code

## Goal
Sameer opens `https://promaxgb10-6116.local:8770` on the Mac (or a phone on the home Wi-Fi), sees a valid padlock, and the mic works, with no SSH tunnel. Kerstin serves TLS itself, using a small local CA. The default without TLS settings stays exactly as today: plain HTTP on `127.0.0.1`.

## Context
- Browsers only allow the mic in a secure context (HTTPS or `localhost`). That's why the README currently needs the SSH tunnel.
- Design (D010): **Uvicorn serves TLS directly** (`ssl_certfile` / `ssl_keyfile`) with a cert from a **local CA generated by `openssl`**. There's no reverse proxy and no new tool to install. `openssl` is already on the GB10.
- **Facts the lead checked on the GB10 (2026-11-04):**
  - LAN IPv4 `192.168.178.55` on interface `enP7p1s0`.
  - mDNS: `avahi-daemon` is active and `promaxgb10-6116.local` resolves.
  - `nordlynx` (`100.84.109.254`) is NordVPN Meshnet. Don't put that address in the cert.
  - **nginx is running on `:80` for other projects. Do not touch it.** Ports 443 and 8771 are free.
  - Sameer may have Kerstin running on `127.0.0.1:8770`. Do your test runs on **port 8771** (`KERSTIN_PORT=8771`) and leave his instance alone.
- Latency: TLS adds a one-time handshake per WebSocket connection plus negligible per-frame encryption. Expect no measurable change in `first_audio_ms`. Confirm with the smoke test.

## Hard rules for this task
- Do not edit or reload nginx. Don't change firewall rules or the system trust store, don't use `sudo`, and don't install packages system-wide.
- Never commit anything under `certs/`. Private keys must have mode `600`. The server must never serve a private key.
- Don't put the NordVPN or Docker bridge addresses in the cert.

## Spec
1. **Config** (`backend/kerstin/config.py`):
   - Add `tls_certfile: Path | None = None`, `tls_keyfile: Path | None = None`, and `tls_ca_certfile: Path | None = None`. The last one is the *public* CA cert, which is offered for download.
   - Extend the relative-path validator to cover them (keep `None` as `None`).
   - Validation (model validator): set both `tls_certfile` and `tls_keyfile` or neither, otherwise raise a clear error. Add a property `tls_enabled: bool`.
2. **Startup** (`backend/kerstin/__main__.py`):
   - Factor out `uvicorn_kwargs(s: Settings) -> dict`. Without TLS it returns exactly today's kwargs. With TLS it adds `ssl_certfile` and `ssl_keyfile`.
   - If TLS is enabled and a file is missing, exit with a message that says `make certs`.
   - On start, log the URL(s) to open (`https://<hostname>.local:<port>` when TLS is on and host is not loopback).
3. **CA download** (`backend/kerstin/main.py`): add `GET /kerstin-ca.crt`, registered before the static mount.
   - If `tls_ca_certfile` is set and exists, serve it with `media_type="application/x-x509-ca-cert"`. Otherwise return 404.
   - Safety check: if the file content contains `PRIVATE KEY`, refuse with 500 and log an error. This catches a misconfigured path.
4. **`scripts/make_certs.sh`** + `make certs`:
   - Write to `certs/` in the project root: `kerstin-ca.key`, `kerstin-ca.crt`, `kerstin.key`, `kerstin.crt`.
   - CA: RSA 3072 or ECDSA P-256, 10 years, `basicConstraints=critical,CA:TRUE`, `keyUsage=critical,keyCertSign,cRLSign`, CN `Kerstin Local CA (<hostname>)`. **If the CA already exists, reuse it** (clients have trusted it). Only `--new-ca` replaces it, with a printed warning.
   - Server cert: 397 days (inside Apple's and Chrome's limits), `extendedKeyUsage=serverAuth`, `keyUsage=critical,digitalSignature,keyEncipherment`, signed by the CA.
   - SANs: `DNS:localhost`, `DNS:<hostname>`, `DNS:<hostname>.local`, `IP:127.0.0.1`, the IPv4 of the interface carrying the default route (`ip -4 route show default` → dev → its address), and any extra `--ip X` arguments. If the default route currently goes through `nordlynx` or another VPN, fall back to the first private-range address (`192.168.*`, `10.*`, `172.16–31.*`) on a physical interface. Print the SANs you chose.
   - Re-running it replaces the server cert and keeps the CA. Set key files to `chmod 600`.
   - End with the next steps: the `.env` lines to set, and the URL to open.
   - Makefile: `certs: ## create local CA + server cert for HTTPS on the LAN` → `bash scripts/make_certs.sh`, and add it to `.PHONY`.
5. **`.gitignore`:** add `certs/`.
6. **`.env.example`:** add a commented HTTPS block:
   ```
   # HTTPS on the LAN (make certs). Without these, Kerstin serves plain HTTP on 127.0.0.1.
   # KERSTIN_HOST=0.0.0.0
   # KERSTIN_TLS_CERTFILE=certs/kerstin.crt
   # KERSTIN_TLS_KEYFILE=certs/kerstin.key
   # KERSTIN_TLS_CA_CERTFILE=certs/kerstin-ca.crt
   ```
   Add a comment that `0.0.0.0` makes Kerstin reachable from the LAN (and NordVPN Meshnet peers) **with no auth**, so use it only on a trusted home network (D010).
7. **`scripts/check_env.sh`:** if `KERSTIN_TLS_CERTFILE` is set, check that the cert and key exist and that the key is mode 600. Warn if the cert expires within 30 days (`openssl x509 -checkend 2592000`) and print its SANs. Read-only.
8. **`scripts/smoke_test.py`:**
   - Add `--cafile` (default: `settings.tls_ca_certfile`).
   - For `wss://` URLs, build an `ssl.SSLContext` with that CA and use it for both `websockets.connect` and the `httpx` health call.
   - Default `--url`: `wss://localhost:<port>/ws` if `settings.tls_enabled`, else `ws://127.0.0.1:<port>/ws` (port from settings).
   - Plain `ws://` behaves exactly as today.
9. **`frontend/index.html`:** footer text only. Replace the SSH-tunnel hint with "Mikrofon braucht HTTPS oder `localhost` – siehe README (HTTPS im LAN)". `app.js` already picks `wss://` on HTTPS, so don't change it.
10. **`README.md`:** rewrite "Using it from the Mac" as "Using it from the Mac / phone (HTTPS)", covering:
    - on the GB10: `make certs`, the `.env` lines, `make run`;
    - trusting the CA once: download `https://promaxgb10-6116.local:8770/kerstin-ca.crt` (the browser warns this one time) or `scp` it;
      - **macOS:** open it → Keychain Access → System → the cert → Trust → "Always Trust". Chrome and Safari use this; Firefox needs its own import or `security.enterprise_roots.enabled=true`.
      - **iOS:** open the URL in Safari → install the profile → Settings → General → About → Certificate Trust Settings → enable.
      - **Android:** Settings → Security → Encryption & credentials → Install a certificate → CA certificate.
    - the fallback URL by IP (`https://192.168.178.55:8770`), in case `.local` doesn't resolve;
    - the SSH tunnel kept as a short fallback;
    - "Use headphones" kept.
11. **Tests** `backend/tests/test_tls.py` (no network, no real crypto needed; dummy PEM text files in `tmp_path` are fine):
    - `Settings` with only `tls_certfile` → validation error; both set → `tls_enabled` is True; neither → False.
    - `uvicorn_kwargs` without TLS equals today's kwargs. With TLS it contains `ssl_certfile` / `ssl_keyfile`.
    - `GET /kerstin-ca.crt` → 404 when unset; 200 with the PEM body when set; 500 when the file contains `PRIVATE KEY`. Use FastAPI `TestClient` and monkeypatch `kerstin.main.settings`. The lifespan doesn't need to run.
12. **Run it** (port 8771, Sameer's instance untouched):
    - `make certs`.
    - Start Kerstin with the TLS env vars, `KERSTIN_HOST=0.0.0.0` and `KERSTIN_PORT=8771`. Use environment variables for this run, not Sameer's `.env`.
    - `curl --cacert certs/kerstin-ca.crt https://localhost:8771/health` and `curl --cacert certs/kerstin-ca.crt https://192.168.178.55:8771/health`.
    - `curl --cacert certs/kerstin-ca.crt --resolve promaxgb10-6116.local:8771:192.168.178.55 https://promaxgb10-6116.local:8771/health`.
    - `curl ... /kerstin-ca.crt`.
    - `make smoke` via `.venv/bin/python scripts/smoke_test.py --url wss://localhost:8771/ws --cafile certs/kerstin-ca.crt`.
    - Run `avahi-resolve -4 -n promaxgb10-6116.local` and report the result.
    - Stop the server. Paste all outputs into the report.
